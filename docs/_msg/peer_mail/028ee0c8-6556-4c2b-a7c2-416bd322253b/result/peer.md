[완료] 따라 읽기 창 — 크롬 확장 반영 (커밋 안 함, 리규형님 실측 전)

■ 동작 — 요청 1~7·9·10 그대로
- 오른쪽 클릭 "선택한 글 읽기"·빨간 점 둘 다: 고른 글에 빈 줄이 없으면 창, 있으면 창 없이 고른 것만 읽는다.
- 문구·버튼·영어 문구는 요청 그대로. Enter = 따라 읽기(그 문단 처음부터 지금 페이지 끝까지 — 고른 순간 페이지에 있는 글만), [이 말만 읽기]·바깥 클릭 = 그 문단 전체, Esc = 안 읽고 닫기.
- 창 = Paseo confirmBox 값 그대로(어두운 배경막 rgba(0,0,0,0.45) 포함), 맨 바깥 페이지의 보이는 영역 가운데(선택이 안쪽 iframe 에 있어도).
- 형광펜: 넓힌 범위를 드래그 읽기 글로 넘기므로 드래그 읽기와 같다 — 빈 줄 문단마다 따로 합성하고 그 조각 단위로 칠한다(구글 음성 2000바이트 넘는 문단은 더 잘게, 단어 위치를 주는 내장 음성은 단어 단위). 이전·다음·Ctrl 단축키도 그 문단 단위.
- 글 상자(textarea) 안 선택도 같게 동작(형광펜만 없음).

■ 이쪽이 정한 것
1. 문단 = 드래그 읽기의 빈 줄 문단 그대로(브라우저가 고른 글을 옮길 때 넣는 빈 줄).
2. 탭 전환: 창이 떠 있는 탭이 숨으면 아무것도 읽지 않고 닫는다(PC 앱 "앞 창이 바뀌면 닫기"와 같은 쪽). 다른 주소로 가면 페이지와 함께 사라진다.
3. 아래 글 상한 없음 — 실측(ego): 위키백과 제2차 세계대전(텍스트 노드 1.6만) 앞쪽 문단에서 따라 읽기 범위 17.6만 자 0.07초, 이 말만 읽기 0.002초.

■ 리규형님 판단이 필요한 것 (지금 상태는 바꾸지 않음)
A. "글 끝" = 페이지 맨 끝이라, 위키백과에선 참고문헌·사이트 바닥글("Code of Conduct … Mobile view")까지 읽는다.
   - 그대로(요청 문구대로, 멈추면 됨) / 본문 끝까지(아이콘 전체 읽기처럼 본문 판정 Readability 를 써서 본문만, 선택이 본문 밖이면 페이지 끝)
B. 크롬은 <p> 뒤에만 빈 줄을 넣는다(제목·목록·div·그림 설명 뒤엔 줄바꿈 하나). 그래서 그것들 바로 뒤 <p> 를 고르면 "이 말만 읽기"가 제목·목록·그림 설명부터 읽는다(위키백과 실측: 그림 설명 + 다음 문단이 한 문단). 드래그 읽기도 같은 정의라 이전·다음 크기는 같다.
   - 그대로(드래그 읽기와 같은 정의) / 창의 문단만 DOM 블록 기준(p·제목·목록 항목·div 하나)으로 — PC 앱(UIA)에 가까워지지만 드래그 읽기 문단과 달라진다

■ 바뀐 파일 (BluemingWebReadAloud)
- js/page-ui.js — captureSelection(물어보기·넓히기), 문단 찾기(paragraphRange·paragraphEdge·spotBeyond·rangeText), 창 askFollow·FOLLOW_CSS
- js/events.js — readSelectionInTab 갈림, askFollow(맨 바깥 페이지에 창), 창 답 메시지 받기
- _locales/en·ko/messages.json — selection_follow_message·selection_follow_this_only·selection_follow_follow
- README.md — 따라 읽기 줄 추가 + 10-28 글 규칙에 맞게 옛 설명 고침

■ 확인 방법
1. chrome://extensions 에서 확장 새로고침, 열려 있던 페이지도 새로고침.
2. 기사 문단에서 몇 글자만 드래그 → 빨간 점(또는 오른쪽 클릭 "선택한 글 읽기") → 창. Enter → 그 문단부터 형광펜이 문단마다 내려간다 / [이 말만 읽기] → 그 문단만 / Esc → 읽지 않음 / 바깥 클릭 → 그 문단만.
3. 두 문단에 걸쳐 드래그 → 창 없이 고른 것만.
4. 창을 띄운 채 다른 탭에 갔다 오기 → 창 없음, 읽지 않음.
로컬 시험(ego): 문단 넓히기 8경우, 창 Enter·Esc·바깥·상자 안·탭 숨김 모두 기대대로, 페이지 선택은 매번 그대로 복원. 어사이드에서 실제 확장으로 해 보는 실측은 아직.
