■ 답 두 가지
- 동시 처리: 됩니다. 요청마다 스레드가 따로이고, 노을 라이브 연결은 각각 따로 최대 12개까지 동시에 엽니다(13번째부터는 자리가 날 때까지 기다림). 12개를 동시에 보내 12개가 모두 처리기 안에 함께 있는 것을 시험으로 확인했습니다.
- 요청을 끊으면: 라이브 연결도 닫힙니다. 확장이 요청 연결을 닫으면 창구가 0.1초 안에 알아채 session.close 를 보내고 라이브 연결을 닫습니다(웹소켓 자체는 Paseo 처럼 3초 뒤 정리). 다시 시도도 하지 않습니다. 자리를 기다리던 요청이면 연결을 열지도 않습니다. 실제 소켓을 닫아 알아채는 것을 시험으로 확인했습니다.

■ 규격 — POST http://127.0.0.1:51888/v1/tts/noeul
- 머리글: Origin 이 chrome-extension:// 로 시작해야 함 · Content-Type application/json · Content-Length 필수(16KB 이하)
- 본문: {"v":1,"text":"…","lang":"ko"}
  · v 는 정수 1 · text 는 비지 않은 문자열이고 다듬지 않고 그대로 읽힙니다 · lang 은 ko·en·ja·zh·es·fr·ar 중 하나(없으면 ko)
- 성공: 200 · Content-Type audio/wav · 본문 WAV(PCM 16비트 한 채널 24kHz)
  · 앞뒤 무음은 Paseo 처럼 첫 소리 앞 두 조각, 끝 소리 뒤 두 조각(각 약 0.2초)만 남깁니다
  · 머리글 X-Usage-Key: 12글자 = 쓴 OpenAI 키의 키별 사용량 칸 이름(sha256 앞 12, Paseo usageKeyMark·이 앱 key_mark 와 같은 계산)
- 실패: 상태 번호 + {"ok":false,"code":"…","error":"화면에 그대로 쓸 한국어 문장"}
  · 400 bad_request — 본문·v·text·lang·JSON·길이가 틀림
  · 403 origin · 413 size
  · 503 no_key — Paseo 키 파일에 OPENAI_API_KEY 가 없음
  · 401 ip_not_authorized — OpenAI 가 이 PC 의 IP 를 허용하지 않음
  · 401 unauthorized — OpenAI 가 키를 거절(괄호에 OpenAI 오류 코드)
  · 504 timeout — 전체 시간 초과
  · 502 no_audio — 노을 무응답(아래 다시 시도를 다 쓴 뒤) 또는 원문이 아닌 말로 시작
  · 502 connect — 연결 오류(괄호에 HTTP 번호) · 502 server — 노을 오류 이벤트(괄호에 OpenAI 코드)
  · 500 internal · 499 cancelled — 확장이 끊었을 때(받는 쪽이 없어 실제로는 가지 않음)
  · 404 {"ok":false,"reason":"path"} — 이 앱이 옛 판(노을 길 없음)일 때. 옛 판을 알아채는 데 쓸 수 있습니다
- 기다림: 이 앱 쪽 상한도 max(90초, 글자 수 × 0.3초 + 30초)로 확장과 같은 공식입니다.

■ 노을 부르는 법 — 낡은 11-17 판이 아니라 Claude State Bar 통보 9f350d9f 와 Paseo tts.ts 11-18 판을 따름
- 순서·지시문: session.start(instructions = 낭독 정책만) → session.started 뒤 session.instructions.append(liveReadPrompt) → 입력 무음 0.1초마다. commentary 는 쓰지 않습니다.

- Paseo 와 다른 점 하나: OpenAI 가 키·IP 를 거절하면(401) 다시 해도 같아서 바로 실패합니다. 최종 오류는 같고 기다림만 짧아집니다.
- 끝 판정: 실제 소리(표본 600 초과) 뒤 1.5초 조용하면 끝, 받아쓴 글이 원문을 다 읽었으면 0.3초, 다 읽은 뒤 새 말이 받아써지면 바로 끊음.
