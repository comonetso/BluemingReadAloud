## 1. 설정 페이지 간격 변경 즉시 반영
- 플레이어가 speedStep 변화를 지켜보다가(js/page-ui-host.js:17) 읽는 중이면 재생 바 목록을 새 간격으로 바꾸고, 지금 속도를 가장 가까운 값(가운데면 빠른 쪽)으로 맞춰 재생 바에서 고른 것과 같은 경로(applyParams)로 소리·저장에 반영(onSpeedStep 261)
- 어사이드 실측: 읽는 중 1.8x 에서 간격 0.25 로 → 목록 11개, 1.75x, 실제 재생 속도 1.75, 저장 1.75

## 2. 속도 단축키 Ctrl+← / Ctrl+→ — 확장에서 됩니다(조건 있음)
- 방법: 재생 바 코드(js/page-ui.js:615)가 재생 바가 떠 있는 동안 페이지 창(window)에서 keydown 을 가장 먼저(capture) 받아 preventDefault·stopImmediatePropagation 하고 플레이어에 한 칸 명령을 보냄. 플레이어가 지금 목록에서 한 칸 옮겨 applyParams 로 반영·저장, 끝에서는 그대로(stepSpeed 272). 연달아 눌러도 칸을 건너뛰지 않게 직전에 보낸 값 기준으로 셈
- 재생 바가 사라지면 리스너를 뗌(693) → 원래 단어 이동. Ctrl+Shift·Alt 조합과 한글 조합 중 키는 건드리지 않음
- 이쪽 리규형님 결정: 일시정지 중에도 재생 바가 떠 있으면 동작 / 맨 바깥 페이지만
- 어사이드 실측(실제 키 입력): 1.3x 에서 Ctrl+→ 1번 → 1.4x, 빠르게 3번 → 1.7x, 5번 더 → 2.0x 에서 멈춤, Ctrl+← 2번 → 1.8x. 매번 재생 속도·저장값·재생 바 표시 일치. 읽는 동안 페이지는 Ctrl+→ 를 못 받고 입력창 커서도 그대로, Ctrl+Shift+→ 는 페이지에 그대로 감, 멈춘 뒤 Ctrl+→ 는 다시 페이지로 감

## 안 되는 범위와 이유
- 키 입력은 포커스가 있는 문서에만 간다. 재생 바가 있는 맨 바깥 페이지에 포커스가 있을 때만 된다
- 안 됨: 주소창·다른 탭·다른 창에 포커스, 페이지 안쪽 틀(iframe — 동영상·외부 편집기·메일 본문) 안에 포커스, 확장이 못 들어가는 화면(어사이드 채팅 — 재생 바 자체가 없음)
- 대안 검토: 브라우저 단축키(chrome.commands)는 브라우저 어디서든 되지만 읽지 않을 때도 Ctrl+←/→ 를 늘 빼앗아 단어 이동이 망가지고, 미리 정해 둘 수 있는 단축키 4개(Alt+P·O·쉼표·마침표)를 이미 다 써서 사용자가 브라우저 설정에서 직접 지정해야 함 → 쓰지 않음. 안쪽 틀까지 잡으려면 형광펜이 들어간 틀에도 같은 키 리스너를 달고 명령 통로를 더 만들면 됨(이번엔 하지 않음)
