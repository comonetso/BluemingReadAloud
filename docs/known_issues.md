# 알려진 문제 — 해결 대기

지금 고치지 않기로 하고 남겨 둔 문제들. 고치기 시작할 때 여기서 꺼내고, 끝나면 지운다(세션 로그에 기록).

## 원문 위 형광펜이 정확하지 않다 (2026-10-28 리규형님)

- **증상**: 읽는 글 위에 칠하는 노란 형광펜이 마음에 들지 않는다 — 리규형님 "여전히" (예전부터 이어진 불만).
  크롬 확장(BluemingWebReadAloud)의 형광펜은 정확하다.
- **왜 다른가**: 크롬 확장은 웹페이지의 HTML 에 직접 칠한다(글자 위치를 페이지가 안다).
  이 앱은 다른 앱의 화면 위에 투명 창을 덮어 그린다 — 글자 자리를 UI Automation 으로 물어서(`source_highlight.py`).
  앱이 알려 주는 사각형이 틀리거나, 글이 움직이면 어긋난다.
- **지금 결정**: 당장 고치지 않는다. 문제로 남겨 둔다(2026-10-28 시험 통과 때 리규형님 결정).
- **원인 후보** (확인 안 됨)
  - 칠할 범위를 읽기 시작 때 한 번만 잡고 다시 확인하지 않는다 — 크로미움 계열(VS Code 등)이 화면을 다시 그리면
    범위가 조용히 옮겨 간다(코덱스 분석 `docs/codex_rescue/260929_211454_response_highlight-overlay-vanish.md`)
  - 2026-10-28 부터 문단 통째로 칠한다(Paseo 기준 맞추기 — 그 전엔 줄·조각 단위). 긴 문단은 넓게 칠해진다
  - 스크롤하는 동안은 숨기고, 멈춘 뒤 한 번 다시 묻는다(`SETTLE_TICKS`)
  - 앱마다 알려 주는 정보가 다르다 — 텔레그램은 글자 자리를 아예 알려 주지 않는다(TextPattern 없음)
- **고치기 시작할 때 먼저 할 일**: 어느 앱에서 어떻게 어긋나는지(자리가 밀림·사라짐·너무 넓음·늦게 따라옴) 리규형님께 여쭙고
  그 앱에서 측정한다. 측정 기록에는 글 내용을 남기지 않는다(길이·사각형만).
