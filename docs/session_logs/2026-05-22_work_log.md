## 1. 작업 흐름 (시간순)

### 1-1. STT 비활성화 시 플로팅 컨트롤러 TTS 전용 모드 전환
**배경**: 이전 세션에서 STT 비활성화 시 플로팅 아이콘 숨기기 미해결. 동시에 TTS 중지가 트레이 메뉴에서만 가능해 불편하다는 문제 제기.
**요구사항**: STT 비활성화 시 플로팅 아이콘을 완전히 숨기는 대신, 파란색 TTS 전용 모드로 전환. 클릭 시 TTS 시작/중지 토글.
**처리**:
- 전역 변수 `controller_mode = 'stt'` 추가 (72줄)
- `load_settings()` 내 `controller_mode` 연동 (1039줄)
- `on_stt_toggle()` 콜백에 `controller_mode` 변경 추가 (2061줄)
- `setup_floating_controller()` 내 색상 상수 추가: `TTS_COLOR='#1565C0'`, `TTS_PLAY_COLOR='#E65100'` (1636줄)
- `on_release()` 수정: TTS 모드 시 `tts_playing` 상태에 따라 시작/중지 분기 (1748줄)
- `update_state()` 수정: TTS 모드일 때 파란/주황 표시, 재생 중이면 정지 아이콘 (1779줄)
**결과**: STT 비활성화 → 파란 버튼, 클릭 → 선택 텍스트 TTS 시작, 재생 중 클릭 → 즉시 중지 동작 확인

### 1-2. TTS 청킹 파이프라인 구현
**배경**: 전체 텍스트를 단일 API 호출 → 긴 대기 후 재생 시작. 체감 속도 느림.
**요구사항**: 단락별 청킹 + Producer/Consumer Queue 패턴으로 첫 청크 완료 즉시 재생 시작.
**처리**:
- `speak_text()` 전면 리팩토링 (3019줄)
- `_chunk_text()`: `.?!` 및 `\n`으로 문장 분리
- `_synthesize_chunk()`: 청크별 단일 API 호출
- `_speak()` 내 Producer 스레드(합성) + Consumer 루프(재생) 분리
- `stop_current_playback()`에 `sd.stop()` 추가
- sounddevice로 직접 float32 재생 (`winsound.PlaySound` 파일 방식 제거)
**결과**: 첫 문장 빠른 시작, 이어서 다음 문장 끊김 없이 재생

### 1-3. SSML break 태그 제거 (이글거림 원인 해결)
**배경**: 사용자가 "이글거린다, thinking 하는 느낌"이라 표현. Chirp3-HD 모델의 과도한 감정 표현 + SSML break 태그 조합이 원인.
**요구사항**: 정량적으로 정식으로 읽어주는 느낌, 속도만 설정하면 됨.
**처리**:
- `_synthesize_chunk()` 내 SSML 태그 완전 제거 (3061줄)
- `synthesis_input = google_tts.SynthesisInput(ssml=...)` → `SynthesisInput(text=chunk_text)`로 교체
**결과**: 훨씬 플랫하고 뉴스 낭독 스타일로 개선. 사용자 "많이 좋아졌다" 확인

### 1-4. 비프음 복구
**배경**: STT/TTS 시작 시 삐 소리가 안 남.
**원인 진단 (로그로 확인)**:
- `winsound.Beep()`는 PC 내장 스피커(beep.sys) 전용 → 현대 PC에서 무음
- sounddevice `sd.play()` + `sd.wait()` 방식: `sd.wait()` 리턴 직후 `stop_current_playback()`의 `sd.stop()`이 비프음 중단
**처리**:
- in-memory WAV 생성 (`io.BytesIO` + `wave` 모듈) → `winsound.PlaySound(SND_MEMORY)` 동기 재생
- TTS 비프음: 880Hz, 0.2초 (3096줄)
- STT 시작 비프음: 600Hz, 0.2초 (2488줄)
- STT 종료 비프음: 800Hz, 0.2초 (2684줄)
**결과**: 비프음 정상 동작 확인

### 1-5. 플로팅 컨트롤러 화면 밖 좌표 폴백 추가
**배경**: 빌드된 exe에서 플로팅 아이콘 안 보임. `dist/whisperer_settings.json`의 `controller_position: {y: 1333}`이 화면 범위 초과.
**처리**:
- `setup_floating_controller()` 내 위치 체크 추가: `y >= screen_h` 등 범위 벗어나면 기본 위치(우하단)로 폴백 (1652줄)
- `dist/whisperer_settings.json`의 `controller_position` null로 초기화
**결과**: exe 재빌드 후 플로팅 아이콘 정상 표시 확인

## 3. 시행착오

- **비프음 첫 시도**: `sd.play(beep) + sd.wait()`로 교체 → 로그상 "비프음 완료" 찍히지만 소리 안 남. 원인: `sd.wait()`가 오디오 버퍼 비워짐 기준으로 리턴하는데 `stop_current_playback()`의 `sd.stop()`이 즉시 DAC 출력을 중단시킴. in-memory WAV → SND_MEMORY 방식으로 재해결.
- **위치 문제**: `dist/whisperer_settings.json`에 이전 사용자 드래그 좌표(y=1333)가 저장되어 있어 1080p 화면에서 아이콘 화면 밖. 코드 레벨에서 폴백 추가.

## 4. 발견한 코드베이스 함정

- `winsound.Beep()`는 `beep.sys` 드라이버 경유, 현대 Windows에서 기본 비활성화. 오디오 장치로 소리를 내려면 반드시 `PlaySound` 계열 사용.
- `sd.play()` 후 짧은 소리는 `stop_current_playback()`의 `sd.stop()` 타이밍에 따라 잘려나갈 수 있음. 비프음은 별도 채널(winsound SND_MEMORY)로 격리해야 안전.
- `controller_position`이 이전 디스플레이 설정으로 저장된 경우 화면 범위 초과 가능. 항상 범위 체크 필요.
- Chirp3-HD 모델은 SSML `<speak>` 래퍼 안에 텍스트를 넣으면 감정 표현 엔진이 강하게 개입. plain `text=` 파라미터로 전달 시 더 중립적.
