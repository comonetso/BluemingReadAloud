## 1. 작업 흐름 (시간순)

### 1-1. TTS 중간 청크 끝 잘림 수정 — sd.wait() 교체
**배경**: 중간 단락은 맨 끝 소리가 잘리고, 마지막 단락만 정상이라는 사용자 보고.
**원인 진단**: consumer 루프에서 `sd.get_stream().active` False 감지 직후 다음 `sd.play()` 호출 → sounddevice 내부 버퍼 비움 ≠ 하드웨어 DAC 출력 완료. 마지막 청크는 다음 play()가 없으므로 잘리지 않음.
**처리**: `_speak()` consumer 루프의 active 폴링 루프(11줄) → `sd.wait()` + `tts_stop_event` 체크(4줄)로 교체 (whisperer.py:3149~3156)
**결과**: 잘림 현상 크게 개선. 사용자 확인.

### 1-2. 150ms 무음 패딩 추가
**배경**: `sd.wait()` 교체 후에도 끝이 아주 조금 잘린다는 사용자 보고.
**원인**: `sd.wait()`는 sounddevice 레이어까지만 보장. OS 믹서 → 하드웨어 DAC 버퍼 레이턴시(20~100ms) 별도.
**처리**: `sd.play()` 호출 전 오디오 뒤에 `np.zeros(int(24000 * 0.15))` 무음 패딩 concat (whisperer.py:3150~3151)
**결과**: "이제는 되게 자연스러워" — 사용자 확인 완료.

### 1-3. 특수기호 TTS 전처리 방향 탐색
**배경**: `()`·`[]`·`{}` 괄호 안 내용이 TTS에서 무시된다는 사용자 보고.
**진단**: 원래 코드(`re.sub(r'\([^)]*\)|...', '', text)`)가 모든 괄호를 내용 포함 제거 중이었음.
**탐색 과정**:
  - 소괄호만 제거, 나머지 원본 전달 테스트 → Google TTS가 쉼표 포즈를 무시
  - 쉼표 치환 → Chirp3-HD가 문맥 판단으로 포즈 생략
  - 마침표 치환 → 포즈 너무 김 (청크 분리 + 마침표 억양 이중 포즈)
  - 공백 치환 → 포즈 없이 그냥 흘러감
  - 최종: 마침표로 원복 (사용자 결정 — "특수기호가 자주 나오지 않으니 마침표로")

### 1-4. 특수기호 전처리 최종 확정
**처리** (whisperer.py:3056~3063):
  - `()` 소괄호 + 내용: 전체 제거 (부연 설명)
  - `[{` 여는 대/중괄호: 공백 (내용 유지)
  - `]}` 닫는 대/중괄호: `. ` 마침표 (내용 후 구분 포즈)
  - 나머지 모든 특수기호 (`▷ → = ~ ' " :` 등): `. ` 마침표
  - 연속 마침표 정리 / 시작·끝 마침표 제거

### 1-5. `_chunk_text()` 5자 필터 제거
**배경**: "이어 ▷ 트웬티 원" 에서 "이어"(2자)가 누락되는 버그 발견.
**원인**: 마침표 치환으로 "이어" 가 독립 청크가 됐는데, 최소 5자 필터에 걸려 제거.
**처리**: `len(c.strip()) >= 5` 조건 삭제, 빈 청크만 제거 (whisperer.py:3072~3076)

## 3. 시행착오

- **쉼표 치환**: Chirp3-HD가 문맥상 자연스럽지 않은 쉼표를 무시함. 로그에서도 `, 트웬티 원`처럼 쉼표가 들어가 있었지만 실제 포즈 없음 확인.
- **마침표 치환 1차**: 청크 분리 + 마침표 억양이 이중으로 겹쳐서 포즈가 너무 길었음. 공백으로 전환했다가 사용자 재요청으로 마침표 원복.
- **대괄호 누락**: `[]{}` 를 별도 처리 없이 허용 목록에서도 제외했더니 마침표로 치환되어 내용도 분리됨. 여는/닫는 괄호 별도 처리로 수정.
- **빌드 실패**: 앱이 백그라운드에서 실행 중인 상태로 빌드 시도 → PermissionError. exe 종료 후 재실행.

## 4. 발견한 코드베이스 함정

- **sounddevice `active` vs DAC 완료**: `sd.get_stream().active == False` 시점은 sounddevice 버퍼 비움 기준. 하드웨어 DAC 출력 완료보다 수십~수백ms 빠름. 오디오 끝이 잘리는 버그의 근원. `sd.wait()` + 무음 패딩이 필수.
- **Chirp3-HD 쉼표 무시**: 문맥상 어색한 위치의 쉼표는 Chirp3-HD가 포즈 없이 지나감. 강제 포즈는 마침표 또는 SSML `<break>`만 가능.
- **`_chunk_text()` 5자 필터와 마침표 치환 충돌**: 특수기호를 마침표로 치환하면 짧은 단어가 독립 청크로 분리됨 → 5자 필터에 걸려 누락. 두 기능을 함께 쓸 때 필터 완화 필요.
