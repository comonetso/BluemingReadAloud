"맨 끝에 엔지니어링이다, PRD다 그냥 계속 붙여버려. 개행된 건지 안 된 건지 확인 못 함. 도그푸딩(dogfooding) 할 수 있지. 그리고 특수문자를 영어로 읽어버리네요. 화살표라든가."
**진단**:
- 단일 `\n`은 청크 분할 단락 구분(`\n\s*\n+`)에 안 걸림 → 다 한 단락으로 처리

**처리** (3건):
- 16c 신설: 밑줄 → 공백
- 17단계 정규식 `\s*[^\w\s\.\?\!가-힣,]+\s*` → 양옆 공백 흡수 (`PRD → PR` → `PRD. PR`)
- 22단계 신설: 단일 `\n` → 마침표+공백 (앞 종결부호면 공백만). 단락 `\n\n`은 임시 마커 `\x00PARA\x00`로 보존 후 복원
**결과**: dogfooding 테스트 178자 → 청크 2개 (108+65). 줄바꿈 자리에 마침표 박힘 검증. dev 재시작.

**처리** (0단계 신설, 함수 맨 처음):
```python

```
**결과**: CRLF 178자 케이스 재테스트 — 청크 [0] `... 엔지니어링이다. PRD. PR ... 게이트다. JSDoc.` [1] `디렉토리 컨텍스트 ... 명분일 뿐.` 검증 완료. dev 재시작.

## 3. 시행착오 / 사이드퀘스트 ★

### 3-1. 인용부호 마침표 변환 — 1차 누락
- **잘못된 가정**: 모든 특수기호를 일관되게 마침표로 처리하면 됨
- **발견**: 사용자 "영어도 섞이고 뭐 이상해" → 로그 보니 `'박제'` → `. 박제. ` 끊김
- **복구**: 16b 단계 신설로 인용부호류만 제거 (다른 부호와 분리)
- **교훈**: 부호별로 청각 의미가 다름. 인용부호는 강조 (제거 가능), 괄호는 부연 (구분 필요), 화살표/등호는 관계 (마침표). 일관성보다 의미별 처리

### 3-2. 괄호 마침표 위치 — `(내용 . `의 함정
- **잘못된 가정**: `r'. \1 . '` (앞뒤 모두 공백+점+공백)으로 청각 경계 표시
- **발견**: 사용자 "() 끝날 때 뭔가 이상한 거 내뱉어"
- **복구**: 닫는 쪽 마침표를 단어에 붙임 `r'. \1. '`
- **교훈**: Chirp3-HD는 단독 마침표 ` . `를 "점" 또는 어색한 톤으로 발음. 마침표는 반드시 단어에 붙어야 자연 문장 종결로 인식

### 3-3. 단일 줄바꿈 vs 단락 — 청크 분할이 모름
- **잘못된 가정**: `\n` 줄바꿈만 있어도 청크 분할에서 알아서 처리
- **발견**: 사용자 첨부 텍스트 3줄(`\n` 분리) → 청크 1개로 합쳐짐 → "그냥 쭉 읽어버려"
- **복구**: 22단계 신설 — 단일 `\n` → 마침표+공백, 단락 `\n\n`은 임시 마커로 보존 후 복원
- **교훈**: 청크 분할은 단락 구분(`\n\n`)만 인식. 단일 `\n`도 의미 있는 구분이면 마침표로 전환해줘야 함

### 3-4. CRLF 함정 — 진짜 원인
- **잘못된 가정**: 22단계 줄바꿈 처리 신설하면 끝
- **발견**: 사용자 "지금도 개행된 거 인식 못 함" → 로그 추적 → 클립보드 텍스트가 `\r\n` 형식
- **복구**: 0단계 (함수 맨 처음)에 `text.replace('\r\n', '\n').replace('\r', '\n')` 추가
- **교훈**: **dogfooding 테스트는 실제 입력 경로의 데이터 형식과 정확히 일치해야 함**. Python 문자열 리터럴 `\n` (LF)으로 테스트한 게 실제 사용 경로(pyperclip→CRLF)와 달라 통과해버림. 이번 세션 가장 중요한 교훈

### 3-5. 단위 테스트 자동화 패턴 발견
- **방법**: `ast.parse` + 노드 필터링 + `exec`로 `whisperer.py` 전체 import 없이 두 함수만 추출해서 테스트
- **이유**: 전체 import는 트레이/녹음 등 사이드 이펙트 일어남. 함수만 분리하면 사이드 이펙트 없음
- **활용 가능성**: 다른 단일 함수 단위 테스트도 같은 패턴

## 4. 발견한 코드베이스 함정 ★ (휘발 방지)

- **Chirp3-HD 단독 마침표 함정**: 텍스트에 ` . ` (공백+마침표+공백) 패턴이 있으면 "점"으로 발음하거나 어색한 톤. 마침표는 반드시 단어 끝에 붙어야 함 (`단어. 다음`). 특수기호 변환 시 양옆 공백 흡수 정규식 (`\s*[^...]+\s*` → `. `) 필수
- **Windows 클립보드 CRLF**: `pyperclip.paste()` 결과는 `\r\n` (CRLF). `\n` (LF)만 처리하는 정규식은 매치 실패. 모든 텍스트 처리 함수 첫 단계에서 `text.replace('\r\n', '\n').replace('\r', '\n')` 정규화 필수
- **Python `\w`에 `_` 포함**: 정규식 `[^\w]` 패턴 쓰면 밑줄 `_`은 보존됨. `_`을 제거하려면 명시적으로 `text.replace('_', ' ')` 같은 별도 처리 필요. TTS에서 `my_var`이 "마이언더스코어바"로 발음되는 함정
- **단락 구분 정규식 `\n\s*\n+`**: 단일 `\n`만 있는 텍스트는 단락 1개로 처리됨. 줄 단위 의미 있는 텍스트는 단일 `\n`도 마침표/`\n\n`로 강제 변환 필요
- **PyInstaller 캐시 활용**: 두 번째 빌드부터 Analysis는 캐시 재사용, EXE 단계만 재실행 — 빌드 시간 대폭 단축
- **AST 노드 필터 + exec 패턴**: `whisperer.py`처럼 import 시 사이드 이펙트 큰 모듈에서 특정 함수만 단위 테스트할 때 유용. `ast.parse(src)` 후 원하는 함수 노드만 골라 `compile`+`exec`로 격리 모듈에 주입

## 5. 사용자 핵심 발언 박제 ★

- > "**() [] {} 내용 제거 X. 괄호 시작/끝에 마침표 둬서 듣는 사람이 괄호 구분 인지하게. 안에 중요 정보 있을 수 있어. 쉼표는 Chirp3-HD가 무시해서 못 씀.**"
  - 맥락: WhisperTyper TTS 전처리 정책 결정
  - 적용 범위: 이 앱 TTS 전처리 정책. 괄호 = 청각 경계, 정보 보존. 쉼표는 강제 포즈 안 됨 (마침표만 가능)

- > "**나 같은 경우 주로 (1) 네가 말하는 거 눈 아파서 못 읽을 때 (2) 100라인 쏟아낼 때 TTS로 들어버려.**"
  - 맥락: TTS 입력 텍스트 성격 정의
  - 적용 범위: WhisperTyper TTS는 **Claude 답변 (마크다운 + 한국어 + 코드/링크/이모지 혼재)** 처리가 핵심. 일반 평문이 아님. 마크다운 마커 제거, 박스라인 제거, URL 단어화 등 Claude 출력 특화 전처리 필요

- > "**도그푸딩(dogfooding) 할 수 있지.**"
  - 맥락: 사용자가 직접 적은 텍스트로 dogfooding 테스트하라는 지시
  - 적용 범위: 사용자가 첨부한 텍스트는 그대로 테스트 케이스로 사용. 단, **데이터 형식(CRLF vs LF)도 실제 사용 경로와 일치해야 함**

- > "**맨 끝에 엔지니어링이다, PRD다 뭐 이런 걸 그냥 계속 붙여버리니까 이게 개행된 건지 안 된 건지 확인을 할 수가 없어.**"
  - 맥락: 단일 줄바꿈 TTS 처리 미흡 지적
  - 적용 범위: TTS는 시각 정보(개행) → 청각 정보(포즈) 변환이 본질. 줄바꿈도 청각 구분으로 전환되어야 사용자가 텍스트 구조 추적 가능
