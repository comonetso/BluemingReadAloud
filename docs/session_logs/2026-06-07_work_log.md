## 1. 작업 흐름 (시간순)

### 1-1. 구글 API 키 위치 질문 → .env 전환 요청
**배경**: 사용자 "구글 API키 어디있지? 바껴서 직접 업뎃할게"
**처리**: 인증 구조 파악 — 서비스계정 JSON(`google_credentials.json`) 방식, 경로는 `whisperer_settings.json`이 가리킴. `.env` 없음 확인.
**결과**: 사용자가 "인증키 방식으로 .env에 바꾸자, 복잡해" 요청. 단 "마이그레이션 먼저, 인증은 그 다음" 순서 지정.

### 1-2. TTS "크롬 익스텐션 read-aloud-hrg와 동일하게" 요구
**배경**: 사용자 "지난 세션 TTS 익스텐션 방식으로 해달랬는데 마이그레이션이 엄청 마음에 안 들어. 익스텐션은 마음에 듦. 동일하게 구현. 다섯 마리 풀어 정밀 조사 후 보고."
**처리**: 16마리 조사 워크플로우(15 렌즈 + 종합). 익스텐션 10렌즈(전처리/청크/문장경계/재생엔진/prefetch/TTS엔진/보이스·언어/재생컨트롤/텍스트소스/설정) + WhisperTyper 5렌즈. (처음 5마리로 띄웠다가 사용자 "더 써서 빨리" 요청에 15마리로 확장 재실행)
**결과**: 근본 원인 규명 — ①청크별 sd.play/sd.wait + 0.15초 무음 = 끊김 ②쉼표→마침표 등 과잉 전처리 ③prefetch 부재 ④보이스 정체 차이(익스텐션=Naver Clova / WhisperTyper=Google Chirp3-HD) ⑤char_limit 140(익스텐션 750).

### 1-3. parity 구현 (전처리/청크/gapless) — 직접 순차 구현
**배경**: 사용자 "익스텐션과 아주 동일하게, 다른 거 생각 필요 없어. 3마리 풀든 네 손으로 하든 알아서." → 같은 함수에 얽힌 작업이라 병렬 부적합 판단, 직접 순차 구현 선택.
**처리** (익스텐션 speech.js/document.js/defaults.js 직접 정독 후 1:1 포팅):
- `_preprocess_for_tts`: 보존주의 전환 — 14단계 괄호 양쪽 마침표 폐기, 15단계 쉼표→마침표 폐기(쉼표 보존), 17단계 모든특수기호→마침표 폐기(화살표/도형만 공백). 마크다운 디마크업·URL→"링크"·줄바꿈→마침표·반복압축은 유지.
- `_chunk_text_for_tts`: 익스텐션 `CharBreaker(750, EastAsianPunctuator, 200)` 1:1 포팅 (recombine/get_paragraphs/sentences/phrases/words + merge 재귀). char_limit 140→750.
- `_speak`: gapless 재생 — 청크별 sd.play/sd.wait + 0.15초 무음 폐기 → `sd.OutputStream` 하나로 BLOCK=2400 연속 write. producer maxsize=2 prefetch. 정상종료 시 0.25초 무음 1회 드레인.
- `_synthesize_chunk`: `.copy()` 추가 (frombuffer read-only 방지).
**결과**: 문법 통과 + 격리 단위테스트(AST 추출) 통과 — 쉼표 보존, 750청킹, 화살표 제거 확인.

### 1-4. 5마리 적대적 검증 → 결함 발견
**배경**: 사용자 "다섯 마리 풀어 네 작업 철저히 검증시켜."
**처리**: 5마리 적대적 검증 워크플로우(청크parity/gapless재생/중지엣지/전처리회귀/통합). 1마리가 `py whisperer.py`(GUI) 실행으로 행(hang) → 사용자 "오래 걸린다" 지적에 `TaskStop`으로 중지, 완료 4마리 결과 journal에서 회수.
**결과**: critical 1 + major 2 발견 (아래 §3).

### 1-5. 결함 4개 수정 + 재검증
**처리**:
- 🔴 좀비 스레드: `finally`의 `tts_stop_event.clear()` 제거 + `prod_thread.join(timeout=1.0)` + 전역 `tts_output_stream` + `stop_current_playback`에서 직접 `abort()`.
- 🟠 마이너스 부호: 17단계 노이즈 정규식에서 수학연산자 블록(U+2200~22FF, U+2212 포함) 제외.
- 🟠 sd.stop 무효: 전역 stream 핸들 + stop에서 abort.
- 🟡 괄호 조사분리: 여는괄호→공백, 닫는괄호→제거(공백 아님)로 "정보)도"→"정보도".
**결과**: 문법 통과 + 단위테스트(마이너스 보존, 괄호, 비교연산자) 통과. 사용자 dev 실청 "거의 비슷해" 확인.

### 1-6. 인증 .env 전환 시도 → STT v2 IAM 한계 발견 → 롤백
**배경**: TTS 완료 후 사용자 ".env 인증키 방식" 진행 요청.
**처리**: `.env` 직접파서 + `_make_stt_client`/`_make_tts_client`(client_options api_key) 헬퍼 + from_service_account_file 3곳 교체. 실증 테스트.
**진단**: TTS는 API키로 작동(84KB 합성). **STT v2는 403 IAM_PERMISSION_DENIED** — `speech.recognizers.recognize`는 IAM 권한 필요한데 API키는 IAM 주체가 아님. yeogiaen(ID)/번호 둘 다 동일(권한 문제). STT v1은 API키 OK이나 V2→V1 회귀는 퇴보.
**결정**: 사용자 "V2 좋은데 V1 회귀 말도 안 됨. STT 쓰려면 JSON. 롤백." → 인증 6곳 롤백(JSON 방식). STT 제거는 168곳 얽힘 = 대수술이라 비추천.
**결과**: 기존 `google_credentials.json`(서비스계정) 살아있음 실증 — STT v2+TTS 둘 다 작동. `.env`/`.env.example` 삭제, `.gitignore` 원복.

### 1-7. 빌드 + 검증 잔재 정리
**처리**: `py -m PyInstaller Yeogiaen_WhisperTyper.spec --noconfirm` → `dist/Yeogiaen_STT_Typer.exe` 43.56MB (exit 0). 검증 워크플로우 중지로 남은 `_verify_*.py` 6개 + `_race*_out.txt` 3개 잔재 사용자가 발견 → 삭제.

## 4. 발견한 코드베이스 함정 ★

- **STT v2 = IAM 권한 강제**: `speech.recognizers.recognize`는 IAM 권한. API키는 IAM 주체가 아니라 403. STT v2 쓰려면 서비스계정 JSON 필수. TTS는 API키만으로 OK.
- **gapless 재생 좀비 함정**: producer가 `put(timeout)`에 갇힌 상태에서 consumer `finally`가 `tts_stop_event.clear()`하면, producer while 조건이 되살아나 영구 좀비. → finally에서 clear 금지(다음 _speak 시작부에서 clear), join 먼저.
- **sd.stop()은 OutputStream 무효**: `sd.stop()`은 `sd.play/rec` 전용. `sd.OutputStream`은 `stream.abort()`로 직접 멈춰야. 전역 핸들 보관 필요.
- **노이즈 정규식 U+2200~22FF 위험**: 수학연산자 블록에 U+2212(마이너스)가 포함 → "−5"가 "5"로 부호 손실. 노이즈 제거 시 이 블록 제외.
- **익스텐션 한국어 보이스 = Naver Clova**: read-aloud-hrg는 한국어를 Clova로 읽음(WhisperTyper는 Google Chirp3-HD). 음색 자체가 다름. 단 이번엔 "흐름"만 parity(엔진 유지).
- **익스텐션 청킹 = CharBreaker(750, EastAsianPunctuator, 200)**: Chirp3-HD류 클라우드 보이스는 isGoogleNative 아니라 CharBreaker 경로(speech.js:57). 한국어는 EastAsian(글자 단위).
- **np.frombuffer read-only**: OutputStream.write에 넣으려면 `.copy()` 필요(일부 환경).
