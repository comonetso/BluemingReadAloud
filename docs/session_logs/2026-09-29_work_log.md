### 1-1. 번역 읽기 요구
**배경/요구**: 드래그한 글에 영어·한글이 섞이는데, 주 언어가 아닌 것은 번역을 거쳐 TTS 로 읽어 일관되게 듣고 싶다. 사용자는 "Gemini 3.5 Live Translate" 를 제안했고, 판별 기준으로 "문단 단위 전부 주 언어 아님" 과 "주 언어 90% 미만" 을 물었다.
**처리**: 웹 확인 결과 Live Translate 는 **음성→음성 전용**(글 입력 없음)이라 제외. 90% 기준은 "React 컴포넌트에서 useState hook을 쓰면 됩니다" 가 한글 41% 라 멀쩡한 한국어가 번역되는 반례를 보이고, **문장에 한글이 한 글자도 없으면 번역**을 권장 → 채택. `translation.py` 신설, `tts_engine.SegmentFailed` 추가.
**결과**: 테스트 통과, 사용자 "대부분 잘 돼".

## 4. 발견한 코드베이스 함정
1. **`logging.basicConfig` 무시** — `setup_logging()` 보다 먼저 `main()` 앞부분(단일 실행 확인·창 아이콘)이 `logging.info/warning` 을 부르면 파이썬이 기본 핸들러를 깔고, 뒤의 `basicConfig` 는 오류 없이 무시된다. 그래서 `logs/whisperer_*.log` 가 2026-07 부터 전부 0바이트였다. `force=True` 로 고침. 외부 라이브러리(comtypes·urllib3·PIL·google·grpc)는 WARNING 이상만.
2. **엔진의 첫 `segment` 알림은 `start()` 를 부른 스레드에서 즉시** 나간다(tts_engine 머리 설명). 합성 스레드의 번역은 그 뒤다 → 조각 차례에 번역 결과가 필요하면 "도착 알림"으로 다시 처리해야 한다.
3. **`split_for_reading` 은 짧은 줄을 한 조각으로 합친다**(SHORT_LINE_BYTES 60) → 한국어 줄 + 영어 줄이 한 조각이 되는 일이 흔하다. 번역은 조각이 아니라 조각 안 **문장** 단위로 판정해야 한다.
4. **설정을 콘솔에 통째로 print** 하던 두 곳(save/load) — 키가 들어가면서 그대로 새는 통로였다 → `_mask_keys`.
5. **GDI 글자는 알파를 0 으로 쓴다** — 층 창(레이어드)에 그대로 쓰면 글자 자리에 구멍. 막이 불투명이라 다 그린 뒤 알파를 모두 255 로. 읽기 전 `GdiFlush()`.
6. **`GetBoundingRectangles` 는 화면 밖 줄을 빼고 준다** — 보이는 줄만으로는 문단 크기를 모른다(마지막 짧은 줄 하나면 폭 75px). 크로미움은 DOM 이 바뀌면 잡아 둔 범위의 끝점을 **예외 없이** 옮길 수 있다(코덱스가 크로미움 소스로 확인) → 빈 결과·엉뚱한 좌표가 조용히 온다.
7. **codex_rescue 쓰기 실패** — 이 저장소 루트·`docs` 소유자가 `BUILTIN\Administrators` 라 코덱스가 응답 파일·`.scratch/` 에 못 쓴다. 스크립트가 최종 메시지로 회수하므로 분석은 된다.
