## 4. 발견한 코드베이스 함정

- **텔레그램 데스크톱(Qt)의 UIA 구조** (10-10 실측): 메시지 = `ListItem`(ControlType 50007, `Name` 에 글 통째), 부모 `HistoryInner`(List 50008) → `Ui::ElasticScroll` → `HistoryWidget` → `MainWidget` → `Ui::RpWidget` ×2 → `MainWindow`. 어디에도 TextPattern 없음. TextPattern 은 입력칸 `Ui::InputField::Inner`(Edit 50004)에만 있고, 메시지를 드래그한 직후 포커스가 입력칸에 남아 있으면 "선택 비었음"(`selEmpty=True`)으로 읽힌다. → 빨간 점(`_selection_end_point` None/"none")·원문 형광펜(`no_text_pattern`) 둘 다 불가, 단축키(Ctrl+C)만 된다.
- **빨간 점이 안 뜬 이유는 로그에 안 남는다**: `_handle_selection_button_msg`(`whisperer.py` 1875~)에서 "선택 확인" 결과가 None/"none" 이면 조용히 버린다. 남는 건 브라우저로 걸렀을 때의 `logging.debug` 한 줄뿐. 다른 앱에서 점이 안 뜬다는 보고는 로그로 못 가리고 실측해야 한다.
- **다른 앱이 선택 위치를 알려 주는지 판정하는 법**(안전한 한 자리 조회): 그 앱이 앞 창일 때 `GetFocusedElement` + `ElementFromPoint(커서)` 에서 `ControlViewWalker.GetParentElement` 로 부모 8단계까지 `UIA_IsTextPatternAvailablePropertyId`·`GetSelection` 을 본다. FindAll·전체 범위 호출 없음. 이름·글은 길이만 찍는다(개인 메시지 노출 방지). 이번 스크립트는 임시 폴더에 두었다가 지웠다 — 같은 방식으로 다시 쓰면 된다.
- **트레이 "종료"는 로그를 남기지 않는다**: `exit_program`(`whisperer.py` 1271~1285)은 `tray_icon.stop()`·`root.quit()`·`sys.exit`/`os._exit` 만 한다. 로그만으로는 "사용자가 끔"과 "갑자기 꺼짐"이 구분되지 않는다(이번 세션 두 번 겪음).
- **설치본은 관리자 권한**: 일반 권한 터미널의 `taskkill /F` → "액세스가 거부되었습니다". 명령줄도 `Get-CimInstance` 로 안 보인다. PyInstaller 단일 exe 라 프로세스가 둘(부트로더 ~112K + 본체)로 보인다.
- **개발 모드·설치본 설정·로그가 따로**: 설정 파일은 작업 폴더의 `whisperer_settings.json` — 개발 모드는 프로젝트 루트(단축키 Shift+X, 브라우저 비활성화 꺼짐, 10-10 기준), 설치본은 `C:\Program Files\BluemingReadAloud\`(Ctrl+Alt+D, 켬). 로그도 `logs\` vs 설치 폴더 `logs\`. 테스트 결과를 말할 때 어느 쪽인지 먼저 확인할 것.
- **하단 컨트롤바는 읽기마다 무조건 뜬다**: `_handle_tts_event` 의 `session_start`(3175~3178)에서 `bottom_bar.show`. 리더 창은 원문 위 형광펜이 실패(`ok=False`)하고 "리더 창 사용"이 켜졌을 때만 → 텔레그램에선 둘이 같이 보인다.
