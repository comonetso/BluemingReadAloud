# 표준 워크플로우 템플릿

> AI 에이전트와 협업 시 사용하는 표준 워크플로우 템플릿입니다.
> `.agent/workflows/` 폴더에 `start.md`와 `finish.md`로 분리하여 저장하세요.
> 또는 AI 에이전트에게 "이 프로젝트에 맞게 워크플로우를 커스터마이즈해줘"라고 요청하세요.

---

- **에이전트는 세션 시작 시 첫 응답에 반드시 **프로젝트명(콜어드민 - xxxx)**을 머리말로 포함하여, 인터페이스가 채팅 제목을 자동으로 올바르게 설정하도록 유도하고 제목을 가능한 한글로 표시한다.**

# 🚨🚨🚨 엄청 중요 사항 (CRITICAL - 반드시 준수) 🚨🚨🚨

## ⭐ 1. 코드 수정 전 반드시 설명하고 동의 받기

- **사용자는 개발자입니다. AI가 일방적으로 코드를 수정하지 않습니다.**
- **코드 수정 전**: 무엇을 왜 수정하는지 한글로 친절하고 상세하게 설명
- **사용자 컨펌 후**: 동의를 받은 후에만 코드 수정 진행
- **수정 과정 중**: 각 단계마다 한글로 무엇을 하고 있는지 설명
- **thought(생각 과정)**: 반드시 한글로 작성하여 사용자가 이해할 수 있도록 함
- **갑자기 코드를 수정하는 행위 절대 금지**

## ⭐ 2. 긴 수정 작업 시 단계별 커밋으로 롤백 대비

> **대규모 수정은 반드시 작은 단위로 나누어 진행합니다.**

- **소규모 섹션 단위로 작업**: 한 번에 너무 많은 코드를 수정하지 않음
- **섹션마다 컴파일/빌드 확인**: 각 섹션 완료 후 정상 동작 여부 검증
- **중간중간 Git 커밋**: 각 섹션 완료 시 한글 설명이 포함된 커밋 메시지 작성
- **롤백 용이성 확보**: 오류 발생 시 이전 커밋으로 쉽게 되돌릴 수 있도록 함
- **커밋 예시**: `[수정] 로그인 기능 리팩토링 1단계 - 인증 로직 분리`

# ⚠️ AI 에이전트 필수 준수 규칙 (Critical Rules)

다음 규칙은 모든 프로젝트에서 **반드시 준수**해야 합니다:

## 1. 한글 문서화 (Korean Documentation)
- **모든 문서, Plan, Todo, 생각 과정 등은 한글로 친절하게 작성**
- 코드 주석은 영어 가능하나, 설명 문서는 반드시 한글
- 사용자는 영어를 전혀 못합니다. 반드시 한글로 소통하세요.

## 2. 테스트 파일 관리 (Test File Management)
- 테스트 파일은 `/tmp`에 작성
- 테스트 완료 후 반드시 삭제
- 프로젝트 폴더에 테스트 쓰레기 파일 남기지 않음

## 3. Git 안전 수칙 (Git Safety)
- 원격 URL에 토큰/비밀번호 포함 형태는 문서에 절대 기록 금지
- 중요한 작업 시작 전 반드시 선(先) 커밋 진행
- Push는 사용자 승인 후에만 실행
- **커밋 메시지는 한글로 작성**
- `.file_history/`는 로컬 백업용이므로 `.gitignore`에 포함

## 4. 보안 수칙 (Security)
- API 키, 비밀번호, 토큰을 코드에 하드코딩 절대 금지
- 민감 정보는 `.env` 파일에만 저장
- `.env` 파일은 절대 Git에 커밋하지 않음

# Part 2: 작업 마무리 워크플로우 (finish.md)

```markdown
---
description: 작업 마무리 - 세션 로그 작성 및 Git 커밋
---

# 작업 마무리 워크플로우

## 1. 세션 로그 작성
// turbo
`docs/session_logs/YYYY-MM-DD_work_log.md` 파일 생성

### 포함 내용
- 오늘 작업 요약 (카테고리별)
- 변경된 파일 목록
- 향후 주의사항
- 미해결 과제

### 세션 로그 템플릿
```markdown
# YYYY-MM-DD 작업 로그

## 📋 작업 요약
- (오늘 수행한 작업 개요)

## ✅ 완료된 작업
- (구현된 기능 또는 수정 사항)

## 📁 변경된 파일
- (변경된 파일 목록)

## ⚠️ 주의사항
- (향후 작업 시 참고할 사항)

## 📝 미해결 과제
- (남은 작업 또는 이슈)
```

## 2. Git 상태 확인
// turbo
```bash
git status
```

## 3. Git 커밋
```bash
git add -A && git commit -m "[타입] 작업 요약

- 주요 변경사항 1
- 주요 변경사항 2
- 문서 업데이트"
```

### 커밋 메시지 타입
- `[기능]` - 새로운 기능 추가
- `[수정]` - 버그 수정
- `[리팩토링]` - 코드 구조 개선
- `[문서]` - 문서 추가/수정
- `[설정]` - 설정 파일 변경

## 4. Git 푸시 (사용자 승인 후)
```bash
git push
```

## 5. 마무리 메시지
작업 완료 요약을 사용자에게 출력한다:
- 오늘 완료한 작업 목록
- 커밋된 변경사항
- 남은 작업 또는 다음 단계 안내
```

# 사용 방법

## 방법 1: AI에게 커스터마이즈 요청
1. 이 파일을 새 프로젝트에 복사
2. AI 에이전트에게 다음과 같이 요청:
   > "이 workflow_template.md를 이 프로젝트에 맞게 커스터마이즈해서 `.agent/workflows/start.md`와 `finish.md`로 저장해줘"

## 방법 2: 수동으로 설정
1. `.agent/workflows/` 폴더 생성
2. Part 1 내용을 `start.md`로 저장
3. Part 2 내용을 `finish.md`로 저장
4. 각 파일에서 `(프로젝트별로 추가)` 부분을 해당 프로젝트 규칙으로 수정

## 워크플로우 실행
- `/start` - 세션 시작 시 실행
- `/finish` - 작업 마무리 시 실행

# 커스터마이즈 가이드

프로젝트에 맞게 다음 섹션들을 수정하세요:

| 섹션 | 커스터마이즈 내용 |
|------|-------------------|
| KI 확인 사항 | 프로젝트 관련 KI 이름 추가 |
| 필수 확인 문서 | 프로젝트별 중요 문서 경로 추가 |
| 빌드/테스트 | `npm run dev`, `pm2 show [앱이름]` 등 프로젝트별 명령어 |
| 반드시 준수할 규칙 | AGENTS.md의 Golden Rules 요약 |
| 절대 하지 말아야 할 것 | AGENTS.md의 Don'ts 요약 |
| 커밋 메시지 타입 | 프로젝트 컨벤션에 맞게 수정 |

# 주의사항

- `// turbo` 주석이 있는 단계는 자동 실행됨
- `// turbo-all` 주석을 최상단에 추가하면 모든 명령어가 자동 실행됨
- 중요한 작업에는 turbo 주석을 사용하지 않는 것을 권장
